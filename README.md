## 2 核 4G 到底够不够：两种算法，别只信一种

圈内流传一套“人数 ÷ 5 = 内存 GB”的懒人公式，按它算，20 人的模组服只要 4G 内存，再加系统开销给到 6–8G 稳妥。这套算法省钱，适合纯净生存。

另一边，Minecraft 服务端教程普遍给的建议更保守：4 核 8G 是推荐起步，最低不要低于这个配置，高版本 Java 服吃单核性能和内存。两条口径差一倍，取舍点在于你装多少东西。

插件服的实际瓶颈通常在单核和视距上，不在核数。Minecraft 的大量游戏逻辑跑在主线程：玩家跑图加载区块、刷怪塔运转、红石电路计算，都是一个核在扛。主频 4.5GHz 的 4 核，跑服比 2.8GHz 的 16 核更顺，这不是玄学，是任务分配决定的。

按单核性能排序，battle 顺序大致是：i9-14900K > Ryzen 9 9950X > Ryzen 9 7950X > Ryzen 9 5900X > Gold 6146 > Platinum 8275CL > E5 2666v3。选机型时看 CPU-Z 单核跑分，600 分以上比较稳，14900K、13900K、7950X、9950X 都在这个区间。E5 2666v3 单核太弱，跑 1.18 以上版本会明显吃力。

内存方面，原版服 4G 够用；轻量整合包 8G 起；大型整合包 16G 起。内存不足的表现不是直接崩，是 GC 频繁触发，玩家体感为间歇性卡顿。带宽只看上行，10 人以内 10M 基本够，20 人以上建议 15M 起步，下行多大意义不大。硬盘 50G 起，世界存档会持续增长，备份也占空间。

## 面板服还是 VPS：第一次开服别纠结

雨云的游戏云分两种形态，选错了不是钱的问题，是能不能开起来的问题。

**面板游戏云**给的是一个网页控制台，内置 MCSManager 面板，上传服务端、装插件、开服、备份全在网页上点。带宽固定 50M 上行，IP 是 NAT 端口映射，没有独立公网 IP，靠“域名 + 端口”访问。适合零基础、想十分钟把服开起来的人。

**VPS 游戏云**给的是完整 Linux 或 Windows 虚拟机，SSH 或 RDP 能登，想跑几个服跑几个服。带宽按所选配置走，可以选独立公网 IP。适合要折腾环境、或者一台机器同时跑 MC 服、网站、机器人的人。

判断规则很直接：第一次开服选面板服，先跑起来；等你开始琢磨“我要装 BungeeCord 做群组服”的时候，再换 VPS 不迟。

线路也会影响体感。以雨云为例，江苏镇江是 NAT 网络（多用户共用公网 IP，可加钱选独立公网 IP），提供 15 个端口；浙江宁波有便宜的独立公网 IP，但走电信单线，高峰期其他运营商延迟较高；镇江和宿迁都是 BGP 线路，各运营商延迟都比较低。玩家主要来自哪家运营商，比机房名字更值得看。

## 从零开起来：Paper 插件服完整流程

### 第一步：选核心

服务端核心分四类：原版服、插件服、模组服、混合服。插件服走 Paper 或 Spigot。

Paper 是 Spigot 的高性能分支，性能和优化选项更好，兼容大部分 Bukkit 和 Spigot 插件，是大多数朋友服、插件服的推荐选择。Spigot 兼容性强，但性能和特性不如 Paper。

如果你还想同时跑模组和插件，Mohist 融合了 Forge 与 Bukkit/Spigot，但它只更新到 1.20.2 版本，1.21 之后就别指望它了。Fabric 和 Forge 属于模组服路线，跟插件服不是同一套生态，别混着买。

### 第二步：对 Java 版本

这是最容易出错的一步，装错了服务端直接起不来。

| 需要的 Java 版本 | Minecraft 游戏版本 |
| --- | --- |
| JDK 8 | 1.7 及以下 |
| JDK 11 | 1.8 ~ 1.16 |
| JDK 17 | 1.17 ~ 1.19 |
| JDK 21 | 1.20 及以上 |
| JDK 25 | 26 及以上 |

旧教程里“1.17 以下选 Java 8，1.17 以上选 Java 17”的说法已经过时，1.20 往上要用 JDK 21。

### 第三步：开端口

MCSM 面板自身要用两个端口：23333 跑 Web 面板，24444 跑 Daemon 守护进程。Minecraft 服务端默认走 25565。

NAT 机型要先去雨云控制台的“NAT 端口映射”里建规则：协议选 TCP+UDP，内网端口分别填 23333、24444、25565，外网端口用系统随机分配的（范围 10000–60000），提示被占用就自己另填一个。独立公网 IP 的机型可以直接用默认端口。

### 第四步：装 MCSM 面板

MCSManager 是一款开源、分布式、一键部署的面板，支持 Minecraft 和 Steam 游戏服务器，能集中管理多台物理服务器、动态创建实例、分角色授权。雨云面板服已经预置好，VPS 机型需要自己装。

root 权限下执行一键脚本：

bash
sudo su -c "wget -qO- https://script.mcsmanager.com/setup_cn.sh | bash"


装完用浏览器访问 `http://服务器IP:23333/`，NAT 机型把 23333 换成你映射出来的公网端口。之后在面板的“节点”里填远程节点 IP、24444 对应的公网端口和 Daemon 密钥。

### 第五步：上传核心、写启动命令

下载对应版本的 Paper 核心（例如 `paper-1.21-50.jar`），在 MCSM 里新建实例，把 jar 传上去，启动命令填这一行：

bash
java -server -Xms128M -XX:MaxRAMPercentage=95.0 -Dfile.encoding=UTF-8 -Duser.country=CN -jar paper-1.21-50.jar


几个参数各管一件事：`-XX:MaxRAMPercentage=95.0` 限制 JVM 最多用系统可用内存的 95%；`-Xms128M` 设初始堆大小，启动时不预占大块内存；`-Dfile.encoding=UTF-8` 防中文乱码；`-Duser.country=CN` 让部分插件走国内镜像源。

如果用的是 JDK 25 + Docker 那套环境，命令可以换成：

bash
java -Xms1G -XX:MaxRAMPercentage=90.0 -XX:+UseZGC -jar server.jar nogui


`-XX:+UseZGC` 启用 ZGC，大内存低延迟，适合长时间运行的服务端，能减少卡顿。这个参数只有 JDK 15 及以上正式支持，低于 JDK 15 必须去掉。`nogui` 表示不启图形界面，服务端在后台跑就行。

一台机器开多个实例时，每个实例都要设清晰的内存上限，否则互相抢资源，几个服一起抖。

### 第六步：同意 EULA

首次启动会生成一堆文件，日志里出现 `You need to agree to the EULA in order to run the server` 是正常现象。打开 `eula.txt`，把里面的 false 改成 true，再启动一次。日志刷到 `Done` 就是开服成功了。

### 第七步：改 server.properties

新手最常动的几项：

- `server-port=25565`：服务端口
- `online-mode`：正版验证，公开服建议 true
- `motd=`：服务器列表里显示的名字
- `view-distance`：视距，性能和内存杀手
- `max-players=`：人数上限
- `white-list=`：白名单，建议开
- `difficulty=`：难度

改完配置要重启实例才生效。

### 第八步：让朋友连进来

客户端“多人游戏 → 添加服务器”，地址填 `公网地址:端口`，中间用英文冒号。NAT 机型要填 25565 映射出来的那个公网端口，不是 25565 本身。实际长这样：`zjh.rainplay.cn:23310`。

## 插件服最容易踩的四个坑

**Java 版本和核心版本对不上。** 服务端一起来就报错退出，日志第一行就在提示 class 版本不兼容。对照上面的表重装 JDK，比反复改启动参数有用。

**`online-mode=false` 的冒名风险。** 日志出现 `OFFLINE/INSECURE MODE` 提示时，服务器不再向官方验证用户名，任何人可以用任意名字登录，冒名、权限劫持都可能发生，被 ban 了换个 ID 还能进。朋友私服也一样，至少把 `white-list=true` 打开，只放可信玩家进来，管理员权限只给必要的人。

**把面板端口当成游戏端口。** 23333 是 MCSM 的网页入口，25565 才是 Minecraft 的入口，NAT 机型两者都要经过各自的映射端口。客户端连不上，先回头确认填的是哪一组数字。

**多个实例不给内存上限。** 两个服都写 `MaxRAMPercentage=95`，第一个服吃掉大部分内存，第二个服启动就开始 OOM。每个实例分配清楚的上限，或者干脆分开机器。

启动失败的排查顺序固定下来：Java 版本是否匹配 → jar 路径是否正确 → 目录权限 → 端口是否被占用 → 内存参数是否超过机器可用内存。按这个顺序走，基本两三轮就能定位。

## 开起来之后：备份、重启和性能判断

插件服的日常运维就三件事，MCSM 的计划任务全都能自动做。

**每日定时备份**，范围包括 `world/`、`world_nether/`、`world_the_end/` 三个存档目录加核心配置文件，保留最近 7–14 份，旧备份自动清理，防止磁盘被撑爆。备份文件有条件的话同步到对象存储或异地机器，别和服务器放在同一个篮子里。

**每日低峰定时重启**，比如凌晨 4 点。重启前用计划任务提前 5 分钟、1 分钟各广播一次提醒。小服也建议重启，长期运行的资源碎片和异常会累积。

**定时执行 `save-all`**，对 IO 压力不高的小服能明显降低意外崩溃后的回档幅度。

开了崩溃自动重启的，记得配上重启冷却时间和最大重启次数，否则崩溃死循环会把日志刷满，机器一直起不来。

卡顿了先别急着升级配置，按这个顺序查：MCSM 监控里看 CPU 是否长期满载、内存是否频繁逼近上限 → 看玩法参数，视距是不是开太高、实体和红石机器是不是太密、刷怪塔是不是过猛 → 看插件本身，有没有高负载插件或配置不合理 → 最后才升级配置，2C4G 升到 4C8G 是最直观的一步。

插件数量不如插件质量和配置重要，视距是性能杀手之一，这两句在排障时比任何参数调优都管用。

面板本身也要上锁：管理员密码 16 位以上，含大小写字母、数字、符号；面板尽量走反向代理上 443 走 HTTPS；能限制访问 IP 或走 VPN 白名单就限制。“能改文件”“能执行命令”“能重启实例”“能下载存档”是四类高风险权限，多人协作时尽量拆开授予，别把管理员账号当共享账号发。

## 什么情况别买贵的

只跟两三个人玩纯净生存，Gold 6146 或 E5 2666v3 的 2 核 4G 足够，首月 40 元上下，没必要上 14900K。
